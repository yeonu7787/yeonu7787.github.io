# Yeonu 개인 블로그

GitHub Pages용 정적 사이트입니다. 홈 / 이력 / 프로젝트 / 블로그와 관리자 편집 화면을 제공합니다.
콘텐츠는 일반 텍스트로 입력하며 줄바꿈을 유지합니다. HTML은 실행하지 않습니다.

## 지금 확인하기
index.html을 브라우저에서 열면 공개 화면을 확인할 수 있습니다.
설정이 비어 있으면 기본 인사말과 빈 목록이 표시되며, 로그인/저장은 비활성 상태입니다.
이름과 기본 문구: index.html, app.js. 디자인: style.css.

## 실제 로그인 및 저장 연결
1. 본인 Supabase 프로젝트를 생성합니다.
2. SQL Editor에서 schema.sql을 한 번 실행합니다.
3. Authentication > Users에서 본인의 이메일/비밀번호 사용자를 생성합니다.
4. schema.sql 마지막 주석의 INSERT를 본인 사용자 UUID로 변경해 실행합니다.
   최초 관리자는 SQL Editor에서만 지정하며 브라우저의 첫 방문자를 관리자로 지정하지 않습니다.
5. 프로젝트 URL과 공개 publishable key를 config.js에 입력합니다.
   service_role / secret key / 비밀번호는 저장소나 config.js에 넣지 않습니다.
6. Authentication 설정에서 공개 회원가입을 비활성화합니다.
7. 관리자 페이지에서 로그인 후 인사말과 이력을 저장하고, 글과 프로젝트를 추가합니다.
   실제 글이 생기기 전까지 공개 목록은 빈 상태가 정상입니다.

로그인 토큰은 메모리에만 보관합니다. 새로고침/탭을 닫으면 다시 로그인해야 합니다.
세션 만료 시 입력 내용을 복사해 보관한 후 로그아웃/재로그인하세요.
서버 연결 오류는 오류로 표시하며, 저장 실패를 성공으로 표시하지 않습니다.

## 다른 작성자
Supabase Authentication에서 사용자를 생성하고 그 사용자에게 계정 정보를 안전하게 전달합니다.
최고 관리자 화면의 '작성자 권한'에 사용자 UUID를 입력합니다.
앱 자체의 이메일 초대 발송은 구현하지 않았습니다.
작성자는 본인 글만 관리하고, 최고 관리자는 모든 글/홈/이력/작성자 권한을 관리합니다.
권한 회수는 기존 공개 글을 삭제하지 않습니다. 최고 관리자 계정은 화면에서 삭제하거나 변경할 수 없습니다.

## GitHub Pages 공개
이 파일들을 저장소 루트에 커밋/푸시한 후 GitHub 저장소 Settings > Pages에서
Deploy from a branch, main 브랜치 / (root)를 선택합니다.
저장소 이름과 계정이 일치하면 https://yeonu7787.github.io/ 로 공개됩니다.
아직 원격 푸시, Pages 활성화, Supabase 연결은 수행하지 않았습니다.
메뉴는 해시 경로를 사용하므로 GitHub Pages에서 새로고침해도 서버 경로 오류가 없습니다.

## 연결 후 필수 확인
- 로그아웃 방문자는 공개 글만 읽으며 API를 직접 호출해도 쓰기가 거부되는지 확인합니다.
- 일반 로그인 사용자에게 편집 권한이 없는지 확인합니다.
- 작성자 A가 작성자 B의 초안을 읽거나 수정/삭제할 수 없는지 확인합니다.
- 작성자는 홈/이력/권한 테이블을 변경할 수 없는지 확인합니다.
- 최고 관리자가 전체 콘텐츠를 편집하고 작성자 권한을 부여/회수할 수 있는지 확인합니다.
- 권한을 회수한 작성자가 다시 API를 호출해도 변경이 거부되는지 확인합니다.
- 새로고침 후 저장한 글이 유지되고 비공개 초안이 공개 목록에서 제외되는지 확인합니다.

실제 서비스가 아직 연결되지 않아 서버 권한/저장 검증은 연결 후 실행해야 합니다.
설계 근거: https://supabase.com/docs/guides/database/postgres/row-level-security
